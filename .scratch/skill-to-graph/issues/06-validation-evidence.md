## Question

前置决策：[图结构与语义映射](04-graph-semantics.md)、[调用契约与分发边界](05-generated-artifact-contract.md)。

如何以有限且有解释力的样本验证保真定义、控制流映射、业务契约和运行能力落实？哪些结论可由静态检查或替身工具支持，哪些必须在真实运行条件下验证？应如何区分包合规、图可加载、图可执行与行为保真的证据？

选择能覆盖不同根因的代表性场景，明确成功路径、人工交互、失败处理和必要副作用的验收方式，以及依赖缺失时可给出的结论。确定是否需要源 Skill 与生成图的对照运行，以及如何报告证据不足；不以模型输出逐字一致、指令文本快照或单次执行成功充当通用保真证明。

是否需要搭建专门验收环境？若需要，按 [AGENTS.md](../../../AGENTS.md) 的边界，明确仓库内如何准备并核对被测图声明的运行依赖、哪些场景使用真实能力或替身，以及两者各能支持什么验证结论。环境配置及生命周期属于仓库验收资产，保持在发布内容之外；环境缺口与转换逻辑缺陷分别记录。

参考：[保真检查清单](../../../references/skill-to-langgraph-mapping.md)、[项目测试约束](../../../AGENTS.md)及前置议题的已确认答案。答案需给出首版验收矩阵、证据要求和停止条件，不在本议题实施测试框架。

## Answer

用户已确认以下验收基础：

- 首版在仓库内准备最小验收环境，满足选定被测图声明的运行依赖。范围随验收样本确定，不建设支持任意 Skill 的通用 harness；环境配置及验收资产留在仓库，模型、服务连接和凭据通过运行配置提供。
- 用少量受控样本隔离转换风险，至少选择一个真实 Skill 作整体检验。样本合计覆盖固定流程、自主决策、混合流程，以及分支循环、人工确认、文件副作用和失败处理；同一样本可覆盖多个风险，不按功能点机械增加测试数量。预期行为来自源契约。
- 源契约是正确性判据：确定性行为检查可观察结果，模型相关行为按明确内容和行为要求审查，必要时人工复核。代表性整体场景可运行源 Skill 与生成图进行对照；对照仅提供辅助证据，双方均违反源契约时仍不能通过，验证结论注明覆盖范围。

### 真实能力与替身

替身用于稳定复现分支、故障及恢复边界；真实文件、脚本等本地能力直接执行，代表性整体场景使用真实模型及所需工具验证实际调用链。

外部服务被替身替代时，证据只覆盖替身支持的行为，不能据此声称真实服务接入通过。必需的真实依赖缺失时，记录对应验收受阻；替身不作为真实依赖已满足的证明，也不随生成图冒充工具实现。

### 首版验收矩阵

矩阵覆盖以下风险，不要求每行独立创建一份样本；少量受控样本与至少一个真实 Skill 可组合覆盖。

| 范围 | 检查内容与证据 | 结论边界 |
| --- | --- | --- |
| 包与交付结构 | 核对源包保留、资源引用、图入口、依赖声明及输入输出映射。 | 仅说明结构和声明检查情况，不代表业务已执行或已保真。 |
| 固定流程、分支及循环 | 受控输入与必要替身驱动代表性路径，检查源规定的顺序、条件、停止语义和可观察结果。 | 只验证已覆盖路径；运行步数受限不等于业务完成。 |
| 自主与混合流程 | 使用真实模型和所需工具运行代表性任务，按源契约检查内容及行为要求，必要时人工复核。 | 不要求未被源契约约束的措辞逐字一致，不外推所有模型判断均正确。 |
| 人工确认与恢复 | 驱动暂停和回复，检查源要求的确认时机、恢复进度及副作用；结合实际声明的恢复能力判断。 | 不将存在检查点等同于任何故障下都不会重复执行。 |
| 文件及脚本副作用 | 真实运行本地能力，检查规定的产物、内容要求及允许发生副作用的时机。 | 文件路径、格式及内容按源契约检查，不以状态字符串替代实际文件。 |
| 失败与外部依赖 | 用可控故障验证源失败策略、权限和依赖缺口报告；实际接入所需外部能力另取真实证据。 | 区分失败处理验证、真实接入验证及环境受阻，不用替身结果证明真实服务可用。 |
| Python 与 CLI 入口 | 两种入口均检查加载和基本调用；复杂行为主要在一条路径深入验证，另一条检查输入输出及适用的暂停恢复等入口差异。 | 不仅检查导入成功，也不重复整套复杂用例。 |
| 独立搬移 | 将产物放在新目录运行，检查携带的源包资源读取和路径解析，确认不依赖原包绝对路径。 | 按已声明的外部运行条件验证可搬移性，不要求产物包含外部服务或工具环境。 |

代表性整体场景可补充源 Skill 与生成图的对照观察；最终判断仍依据源契约，双方相同的违约行为不能通过。首版不将 Docker 构建或托管部署列为默认必验项。

### 完成标准与记录

首版选定的必验场景均取得所需证据、满足源契约，且不存在已知违约时，判定该验收范围通过。验收范围及预期须在判断结果前明确，避免通过缩减范围掩盖已发现的问题。

未运行、证据不足和环境受阻分别注明，不能计作通过；必验项仍处于这些情形时，对应验收尚未完成。环境缺口不能直接记为转换逻辑失败，已知违约也不能归入单纯证据不足。

记录至少包含源样本与契约要求、运行配置、实际观察、判断依据和未覆盖范围。结论仅针对已声明的验收范围，不扩大为任意 Skill、任意路径均已保真的证明。

### 开发参考中需要校正的建议

后续编写转换指令和验收资料时，核对[转换映射参考](../../../references/skill-to-langgraph-mapping.md) §9：以源语义与行为证据判断保真，拓扑图只能辅助理解，不能要求 agent 图的内部节点与源步骤机械一一对应；两种入口须取得调用证据，加载成功本身不够。

[CLI 与部署参考](../../../references/langchain-cli-and-deployment.md) §10 中的镜像构建自检项按本票的首版范围处理，不加入默认必验矩阵。本票仅完成验收设计，环境、样本和验收执行留待实现阶段。本票结案。
