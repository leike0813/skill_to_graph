## Question

前置决策：[验收场景与证据](06-validation-evidence.md)，以及该议题依赖的转换规则和运行边界。

根据已确定的转换与验收规则，哪些工作需要 Agent 做语义判断，哪些确定性处理应复用现有能力或交由脚本？`SKILL.md` 应直接承载哪些必需流程、输入输出约定及约束，哪些解释性材料需要随包分发？对确需新增的脚本，最低调用契约、用途和调用时机是什么？

明确根目录开发资料与发布目录执行资料的职责，避免两份可独立漂移的规则事实源。按项目要求处理必须随包分发的映射参考，并决定其余资料是否必要。明确哪些规划产物交接给后续 OpenSpec，以及所有关键问题已决、可以进入规格阶段的判据。

编写转换指令及分发资料前，读取[图结构决策](04-graph-semantics.md)、[调用契约与分发决策](05-generated-artifact-contract.md)和[验收决策](06-validation-evidence.md)中记录的参考建议差异，将相关资料校正工作纳入文件范围。

文件职责与发布范围须遵守 [AGENTS.md](../../../AGENTS.md) 中的验收环境边界，将仓库验收资产与发布文件分开安排。

参考：[Skill 包发布与资料要求](../../../AGENTS.md)、[包格式规范](../../../references/agent-skills-package-format.md)及前置议题的已确认答案。答案需提供实现所需的职责和文件范围，不在本议题编写 Skill、脚本、完整 OpenSpec 或实施任务。

## Answer

用户已确认以下分工：

- 采用核心指令、参考资料和少量脚本的结构。Agent 负责理解源契约、分析流程、选择图结构并生成具体 Python 图代码；脚本承担包检查、资源盘点、文件复制及产物的确定性校验。首版直接生成具体图，不引入统一工作流中间语言、通用编译器或额外数据库，脚本不通过关键词匹配决定节点和分支。
- `SKILL.md` 完整承载执行流程、输入输出契约、硬约束、脚本调用及完成条件；包内 `references/` 提供映射例子、解释和必要 API 资料，并注明读取时机。根目录资料继续作为开发知识保留；发布包至少包含按已定决策校正的映射参考，其余资料按执行需要提炼。发布后的 Skill 能独立使用，不依赖开发仓库文件，不维护两套转换规范。

采用脚本辅助工作流的复杂度：包处理和确定性校验值得固化为脚本，语义转换仍由 Agent 完成；没有为转换器引入中间语言、数据库或额外状态机的需求。生成图自身的暂停恢复设施按前置决策落实，与转换器架构分开。

### 最低脚本契约

| 类别 | 输入 | 职责与输出 | 使用时机 |
| --- | --- | --- | --- |
| 包处理 | 源包路径；复制时另有目标位置。 | 检查并盘点源包，输出元数据和文件清单；按需完整复制源包，保留目录结构。 | 分析源包前检查和盘点；生成产物时复制。 |
| 产物检查 | 生成目录。 | 检查代码语法、配置、入口和资源路径等确定性内容，输出检查结果；不负责判断语义保真。 | 图代码及配置生成或修正后。 |

脚本提供 `--help`、明确退出码及稳定的机器可读结果。用途、调用时机、命令和失败处理直接写入 `SKILL.md`；具体参数和结果字段在实现前的规格与设计中明确，复用成熟解析和文件操作能力。

### 输出位置与写入边界

输出位置可选，默认在任务工作目录下使用 `<skill-name>-graph/`。目标已存在或与源包重叠时，报告冲突并另选位置，保留源包和已有文件；不以自动覆盖或递归复制解决冲突。

源包路径仍是唯一必需转换输入。输出位置选择与实际发现的写入冲突处理不构成普遍追加源材料的要求。

### 后续文件范围

| 位置 | 职责 |
| --- | --- |
| `skill-to-graph/SKILL.md` | 发布 Skill 的完整核心执行契约，包括必需流程、约束、脚本调用、验证和汇总责任。 |
| `skill-to-graph/references/skill-to-langgraph-mapping.md` | 按已确认决策校正的映射例子与解释，与必要 API 资料一起按需读取。 |
| `skill-to-graph/references/` 中确有执行用途的 API 资料 | 从开发知识提炼必要内容及来源，保证发布 Skill 独立使用；文件拆分依据实际读取需要确定。 |
| `skill-to-graph/scripts/` | 上述包处理与产物检查两类脚本；脚本名和参数在规格化接口时确定。 |
| 根目录 `references/` | 保留开发知识与来源，校正已记录的设计建议差异，与发布主文件的执行规则保持一致。 |
| 仓库测试、样本和验收环境目录 | 脚本稳定业务行为测试、受控样本、至少一个真实 Skill 及最小验收环境；目录在实现设计中确定，位于发布目录外。 |
| 后续 OpenSpec 变更目录 | 基于本地图及各票结论编写规格、设计和实施任务。 |

参考资料校正同时遵循[运行能力与权限决策](03-runtime-capabilities.md)，特别是工具预授权、禁止规则与外部依赖的区别。脚本测试覆盖可观察业务行为，Skill 指令文本不做静态断言；完整验收按[验收决策](06-validation-evidence.md)执行。

### 规划完成与交接

七票全部解决，且没有影响契约、架构或验收的已知未决问题时，规划完成。地图索引各票答案，后续 OpenSpec 以这些答案为输入，不另复制一套独立决策文档。

前期地图中对未知语义组合及运行与保真差距的担忧，已有映射原则、验收矩阵和证据边界承接；当前没有可进一步明确的实施前阻塞问题。具体样本和运行证据在实现阶段取得；若样本执行暴露新的设计问题，应明确记录并处理，再更新受影响的决策。
