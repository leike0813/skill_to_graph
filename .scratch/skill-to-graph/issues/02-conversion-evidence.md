## Question

项目规定输入为源 Agent Skill 包路径。转换应以哪些包内指令、脚本及资源为依据？包内材料之间出现影响行为的矛盾时，如何识别并提交待澄清问题？

明确合法源包作为完整转换依据的边界，以及转换依据与目标图运行配置之间的区别。

参考：[项目输入与脚本要求](../../../AGENTS.md)、[Skill 包格式与 harness 差异](../../../references/agent-skills-package-format.md)。答案需列出材料职责、取舍规则及冲突处理流程。

## Comments

用户对首轮问题的答复：

- 转换输入：用户指出，“如果提供的包路径是一个合法的 Agent Skill 包，那么理论上不应该需要其他信息。”据此，以合法源包自足为设计前提，不预设源 harness 配置、用户额外说明或 transcript 为必需转换材料。目标图运行所需的工具配置与凭据属于运行能力议题。
- 材料冲突：用户同意列明影响行为的冲突并澄清，不静默选择材料或改写源行为。
- transcript：首轮讨论时项目说明包含适配和转换的表述，但未指定使用环节。用户要求解释为何提出这个问题，未接受将其定义为源 Skill 执行记录的建议。

后续澄清：用户确认原说明中的 transcript 表述是误写，并已从 `AGENTS.md` 删除。重新读取文件后确认删除已生效；相关用途及格式选择不再是本票的待决事项。

## Answer

### 合法源 Skill 包是完整转换依据

用户确认：若提供的路径是合法 Agent Skill 包，理论上不应需要其他信息。转换以该包为完整依据，读取 `SKILL.md` 及相关指令、脚本和被引用资源，识别源契约、流程与能力需求。

不追加源 harness 配置、执行记录或额外用户说明作为默认必需转换输入，也不为转换器规划通用 transcript 适配能力。脚本仍可按项目要求承担必要的确定性、重复性处理，其具体职责由 [Skill 包分工议题](07-skill-package-responsibilities.md)决定。

### 包内矛盾需澄清

包内指令、脚本或资源出现影响行为的矛盾时，列出冲突位置及不同解释的影响，向用户确认应遵循的源契约；不静默选择材料、修改脚本行为或猜测缺失语义。

澄清针对实际发现的矛盾，不为合法且自足的包增加普遍补充材料要求。

### 转换依据与运行条件分开确定

源包声明的工具、权限和外部服务需求属于待保留的源行为。目标图运行所需的工具绑定、模型配置和凭据属于运行条件，由[运行能力与权限议题](03-runtime-capabilities.md)决定，不将这些配置反推为源包缺少转换材料。

本票的原始 transcript 分支来自用户已撤回的误写要求，现已移出规划范围。本票结案。
