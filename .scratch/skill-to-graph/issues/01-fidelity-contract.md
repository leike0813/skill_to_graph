# 如何定义并判断转换前后的行为保真？

Labels: wayfinder:grilling
Type: grilling
Status: resolved
Parent: [skill-to-graph 首版转换决策地图](../map.md)
Blocked by: none

## Question

“功能与输入输出契约完全一致”具体约束哪些可观察行为，哪些差异属于运行载体带来的表达差异？应如何分别判断回复、文件产物、副作用、交互轮次、权限要求、失败处理及流程顺序是否保持一致？对于含模型自主判断的行为，什么证据足以支持保真结论，什么情况下只能报告尚未验证？

以至少一个确定性流程和一个包含模型判断的场景检验定义，明确成功、缺少运行条件、语义不明确和证据不足的处理边界。遵守地图中已确认的缺口处理原则，不预先把“完全一致”解释为逐字输出一致，也不以可运行代替保真。

参考：[项目目标](../../../AGENTS.md)、[契约映射与保真检查清单](../../../references/skill-to-langgraph-mapping.md)。答案需给出后续议题能引用的保真定义和判定边界。

## Answer

用户已确认以下三个边界。术语见[术语表](../../../GLOSSARY.md)。

### 行为保真以源契约为准

转换图必须保留源 Skill 规定的输入、输出要求、文件产物、副作用、确认环节及失败行为。源 Skill 规定的顺序、条件和权限要求也属于行为约束，不能仅凭最终产物相同判断保真。

自然语言表达可以变化，但明确要求的格式、内容和语气仍须满足。只有源契约明确要求逐字一致的内容才逐字比较。

确定性流程示例：源 Skill 要求“等待用户确认后写文件”，图在确认前写入即不保真，即使最终文件完全相同；必须保留确认与写入之间的先后约束。

### 控制流程显式化，保留原有判断空间

图可以将源 Skill 已规定的控制条件显式化，必须保留源 Skill 交给模型的判断空间。不得为提高可控性而自行增加步骤、限制、审批或固定策略。新增限制应作为独立变更另行授权，不纳入本次保真转换。

模型判断示例：源 Skill 要求“资料不足时继续检索”，转换图须保留判断资料是否充分及据此继续检索的能力，不能自行规定最多检索三次；若源 Skill 明确规定三次，则须保留该限制。源 Skill 要求“总结文章”时，措辞变化本身不构成失真，仍需满足其内容、格式等要求。

### 生成结果与验证结论分别报告

“产物已生成”与“已获得保真验证证据”是不同结论。静态检查、成功加载和有限运行分别只能支持各自覆盖范围内的判断，不能据此宣称所有输入、模型判断和执行路径均已保真。

验证结论必须说明所依据的证据、覆盖范围及未验证部分。完整保真仍是转换目标，有限验证不能将未检查部分视为已满足；验收场景、证据形式与检查方法由[验收议题](06-validation-evidence.md)决定。

### 判定与处理边界

| 情形 | 处理与结论边界 |
| --- | --- |
| 产物已生成，且在某些范围取得验证证据 | 分别报告生成结果和证据支持的保真结论，说明未验证部分。 |
| 已确认违反源契约 | 报告具体差异；修正并核验前不能将该差异称为保真。 |
| 必要工具、权限、服务或交互能力缺失 | 报告运行或验收条件缺口，待补齐条件后执行相应验证；不自行替换行为，也不将未验证范围称为已保真。仅环境缺口不能认定转换逻辑错误或阻止生成产物。 |
| 无法可靠判断源指令的含义或存在冲突 | 按项目的澄清规则向用户提问，不自行选择会改变源行为的解释；源 Skill 明确留给模型的定性判断仍按上一节保留。 |
| 证据不足或存在未验证路径 | 明确标注尚未验证的范围，不将生成、加载或有限运行成功扩大为完整保真结论。 |

本议题确定判定原则；转换材料、运行职责、图结构、调用封装和具体验收方式由各自议题继续决定。
