# 源 harness 的能力与权限如何在目标运行环境中落实？

Labels: wayfinder:grilling
Type: grilling
Status: resolved
Parent: [skill-to-graph 首版转换决策地图](../map.md)
Blocked by: none

## Question

源 Skill 所依赖的文件操作、命令执行、外部工具、其他 Skill、委派、会话上下文及用户交互，应由生成图、调用方还是外部服务提供？模型配置与凭据由谁提供，如何避免生成图隐含绑定未经选择的模型？首版需要明确哪些运行前提，如何检查能力是否可用，并按已确认原则报告无法满足的依赖？

区分工具可用性、预授权规则与禁止规则。特别核对映射资料将 `allowed-tools` 当作白名单的建议与包规范资料描述的预授权语义；不因字段名称直接推定目标工具池。说明纯 Python 与 CLI 服务运行时分别需要调用方提供什么，以及有哪些尚需用户选择的能力范围。

参考：[工具与中间件映射](../../../references/skill-to-langgraph-mapping.md)、[harness 字段和权限差异](../../../references/agent-skills-package-format.md)、[运行期契约与两种运行形态](../../../references/langchain-cli-and-deployment.md)。答案需形成职责边界和运行前提。

## Answer

用户已确认以下职责边界：

- 图按源 Skill 的需要复用工具或提供必要实现，具备实际调用路径；运行环境提供可执行程序、工作目录、外部服务及权限。图声明所需外部能力及其调用约定，不承诺调用环境一定具备这些能力。
- 源 Skill 指定的模型或能力要求须保留；未指定时由调用方配置满足需求的模型。凭据由运行环境提供，不写入生成代码，不暗中绑定默认供应商。
- 区分工具存在、调用预授权与调用禁止，按字段实际语义保留源权限约束；有效执行权限须满足目标环境授权，不把 `allowed-tools` 一律当作工具白名单。
- 外部依赖缺失应报告为运行或验收条件缺口，不仅凭该缺口认定图的转换逻辑错误或阻止生成产物；保真验证结论仍限于已有证据。
- 项目可能需要验收环境；若搭建，须满足被测图声明的运行依赖。环境仅为仓库资产，独立于发布的转换 Skill 包和生成图。是否搭建、依赖覆盖及具体配置由[验收议题](06-validation-evidence.md)决定。

### 人工交互与会话状态

图负责在源 Skill 规定的位置暂停、保留流程状态，并在收到用户回复后继续。调用环境负责呈现问题、提交回复，以及提供所需的会话上下文和状态存储。

纯 Python 调用与 CLI 服务可以采用不同接入方式，但须保持相同的业务交互语义。需要暂停恢复时，依照所用运行方式配置必要的会话标识和状态保存设施；具体图结构与加载方式由后续议题确定。

### 其他 Skill 与委派能力

源 Skill 依赖其他 Skill 或 agent 时，图保留调用关系并声明依赖，由运行环境提供相应入口。不默认递归转换和打包所有外部 Skill，也不自行替换委派行为。

源包内已包含且能够直接实现的子流程仍按源指令转换，具体表达方式由[图结构议题](04-graph-semantics.md)决定。

### 交接边界

本票确定运行职责，不要求生成图配齐或保证任意环境中的外部能力。依赖声明和调用契约由[交付议题](05-generated-artifact-contract.md)落实；缺失依赖时报告可识别的运行或验收条件缺口，不能以空工具函数冒充已实现的调用逻辑。

验收环境的必要性、覆盖范围及配置由[验收议题](06-validation-evidence.md)决定，其仓库资产与发布内容的边界已确定。本票结案。
