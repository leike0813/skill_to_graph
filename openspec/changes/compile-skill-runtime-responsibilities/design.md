# Design

## Context

动机及范围见 [proposal.md](proposal.md)。当前发布 Skill 已要求提取源契约、按局部语义构图并验证，但真实 literature-analysis 图的阶段代理重复读取完整源指令，阶段输入只含上次 runtime 返回，批次代理未明确得到语言参数，首次提交推进后禁止再次提交。对应证据保存在 `tests/acceptance/literature-analysis-attention/`；`wait-what` 也有超出源依据的扩写。

## Goals / Non-Goals

**Goals:** 为转换 Agent 提供可直接执行的职责分配与核对方法；在不扩大业务状态和权限的前提下保持约束、数据和修正能力；完成迁入的原 5.2、5.4。

**Non-Goals:** 不构建统一流程中间语言、通用编译器、自动语义评分系统或新 Agent harness；不重写源 Skill 或修改首次失败证据。

## Decisions

### 转换阶段确定职责，运行阶段执行局部任务

扩充现有契约工作表，为每项源约束记下源位置、执行者、实现位置、必要输入及验证方法。固定顺序、数据分支、权限和终止规则进入控制代码；不可确定的语义判断保留给局部 agent。节点指令描述本职任务、适用规则及契约，参考资料按源条件读取。完整源包仍随应用分发。相较每阶段重新解释整份 Skill，这样能减少重复解释及职责冲突；纯自主源仍可使用完整自主区段。

### 明确传递必要上下文，维持权限边界

各图按源需要定义状态或运行上下文，不引入统一 DTO。语言、任务身份、证据范围及必要历史信息须在消费点可见；局部参数来自既有真源。给批次代理补充适用控制信息，不开放额外论文证据、其他 batch、DB 或提交权限。只说“遵循 DB 中的配置”不能替代提供实际值。

### 源决定修正路径，图负责正确表达

对源允许的 payload 修复、重新提交及重渲染逐项定义可达路径，区分准备、首次提交、修订和完成。不能用已推进阶段的一刀切保护阻断合法修正，也不能改成无条件自动重试。副作用恢复和事务限制沿用源及运行环境的实际能力。

### 通过重新转换验证发布指令

先修改发布主文件及映射参考，再按发布 Skill 在新目录转换已有样本；不只手改旧图来宣称转换方法已修复。复用现有驱动、14 项脚本测试与主入口深入/另一入口基本调用的分工。跨阶段参数及修正权限适合做小型行为回归；自然语言与事实依据人工复核，不精确断言指令文本，不以语言字符比例代替判断。对照组单独核验契约遵循情况。

## Risks / Trade-offs

- 局部指令拆分可能遗漏全局义务 → 按源约束逐项追踪，检查阶段及委派接收点。
- 调整后仍可能出现模型事实错误 → 按源证据复核代表性关键结论，区分模型误读与转换缺失，不承诺单次成功代表普遍保真。
- 恢复路径涉及重复副作用 → 仅实现源允许路径，记录未覆盖及无法保证的边界。
- 真实验收受模型和服务条件影响 → 复用已配置条件，缺口单列；安装依赖及启动服务仍遵守授权要求。

## Migration Plan

本次只调整 change 的任务归属并归档首轮。第二轮实施时更新发布指令和必要参考，在新目录生成图、运行及保存结果，原有样本、源包和失败产物保持原样。发布标准不因首轮归档而降低；原 5.2、5.4 在本轮继续为待完成项。
