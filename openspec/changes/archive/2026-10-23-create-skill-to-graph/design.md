# Design

## Context

动机及能力边界见 [proposal.md](proposal.md)，语义依据为[七票决策](../../../../.scratch/skill-to-graph/map.md)。发布目录为空，尚无转换代码或测试工具链；现有开发参考包含已明确需要校正的建议。

共享 Python 环境已有 PyYAML 6.0.3，未安装 LangGraph、LangChain 或 langgraph-cli。OpenSpec 1.14.3 已可用。本阶段只定义实现，后续环境准备遵守项目依赖管理约束。

## Goals / Non-Goals

**Goals:**

- 选择少量、职责完整的辅助脚本，明确其参数、输出及写入边界，让 Agent 保留语义转换责任。
- 使发布 Skill 自足，生成应用可独立搬移，并将执行证据和静态检查结果分开。
- 为实施任务明确文件归属、工具链与首版样本，不将已有决策留给实现者重新猜测。

**Non-Goals:**

- 不构建统一工作流中间语言、通用自然语言编译器、转换器数据库或通用 harness。
- 不在转换阶段配置真实模型凭据、安装外部服务或保证任意环境具备声明的依赖。
- 不把项目测试环境、转化时的会话记录或开发期议题作为发布 Skill 的运行依赖。

## Decisions

### 1. 主文件统领语义转换，参考资料解释机制

`skill-to-graph/SKILL.md` 承载完整流程：检查并盘点源包，识别业务契约与能力需求，按局部语义选择图结构，创建新产物并复制源包，生成具体图与运行说明，做确定性检查与当前条件允许的验证，分别汇报产物及验证结论。

源材料真实冲突时列明位置及影响并澄清；普通语义判断继续按源交给模型的自由度处理。源包路径是唯一必需输入，目标目录可选。框架调用封装与源业务结果分别说明。

主文件直接给出脚本命令、结果字段、退出码及失败处理，引用 `references/skill-to-langgraph-mapping.md` 读取映射例子；生成具体代码时读取精炼的 `references/runtime-api.md`，查核心图机制、agent、配置和入口 API。两份参考不承载主文件缺失的硬约束，不依赖仓库根目录文件。

根目录开发知识保留出处，按各票列出的差异校正，发布执行规则以主文件为准。未选方案是复制全部开发资料并维护两套独立转换规范；那会增加上下文与漂移成本。

### 2. 两个脚本承担确定性工作

发布脚本采用 Python 3.11+。`skill_package.py` 使用成熟的 PyYAML 安全解析元数据，文件操作使用标准库；`check_graph.py` 使用标准库解析 Python、JSON 和本地路径。主文件声明 Python 与 YAML 解析依赖，不自动安装依赖。

| 命令 | 输入 | 成功时的 `data` |
| --- | --- | --- |
| `skill_package.py inspect <source>` | 源包目录 | `source_root`、原样保留的 `metadata`、按包内相对路径排列的 `files`。每个文件记录 `path` 及文件类型。 |
| `skill_package.py copy <source> [--output <directory>]` | 源包及可选新应用位置 | `output_dir`、`source_dir`，分别定位创建的应用和携带的源包。 |
| `check_graph.py <directory>` | 已生成应用目录 | `checked_files`、`graph_entries`，记录实际检查的相对路径及入口配置。 |

默认目标为任务当前目录的 `<metadata.name>-graph/`。复制命令先检查元数据及路径，确认目标不存在且与源包不重叠，再创建应用目录和 `source/<原包目录名>/`。完整复制文件、目录及脚本运行所需属性，不按静态引用裁剪。无法完整读取或复制的内容报错，原包和已有目标不修改；复制中途失败保留诊断和部分产物，不自动覆盖重试或清理用户文件。

检查工具只做可确定的检查：生成代码的语法、`langgraph.json` 必需结构、配置指向的本地入口位置及显式资源路径。它不导入或执行生成代码，不遍历外部运行服务，不通过关键词猜测自然语言引用或判定业务保真。动态入口对象是否可加载属于运行验证。

三个操作共用结果形状：

```json
{"ok": true, "operation": "inspect", "data": {}, "issues": []}
```

`operation` 的枚举为 `inspect`、`copy`、`check`，参数解析无法识别操作时为 `null`。`data` 总为对象，失败可为空；`issues` 总为数组，其元素包含 `code`、`path`、`detail`，与文件无关时 `path` 为 `null`。帮助输出使用普通文本；其余受脚本处理的成功、参数和业务失败均输出上述结构，不让调用方解析完整提示文案。

| 退出码 | 含义 | 问题码 |
| --- | --- | --- |
| 0 | 已完成请求的确定性操作 | 无错误 |
| 2 | 参数或命令无效 | `invalid-argument` |
| 3 | 源包检查失败 | `invalid-source` |
| 4 | 目标已存在或与源重叠 | `output-conflict` |
| 5 | 文件读写或复制失败 | `io-error` |
| 6 | 生成产物的确定性检查失败 | `invalid-artifact` |

`--help` 返回 0 且不产生写入。检查返回 0 只说明所列检查完成，不表明模型、工具、CLI 或语义已验证。

元数据检查遵守开放规范的核心字段和约束；额外的平台字段保留供 Agent 按实际语义处理，不使用某厂商工具白名单代替通用检查。包内行为矛盾和动态引用由 Agent 分析，工具不将它们伪装成已由解析器判定。

此处约定的是辅助脚本的报告结构，不是源业务契约或通用工作流中间表示。未选方案是仅靠 Agent 手工盘点、靠正则解释流程，或构建大型编译框架。

### 3. 生成应用分离原包和新增代码

推荐默认布局如下，只有源流程需要时才拆分更多代码文件：

```text
<skill-name>-graph/
  source/<original-package-name>/...
  skill_graph/
    __init__.py
    graph.py
  langgraph.json
  pyproject.toml
  README.md
```

`source/` 保存完整包，`skill_graph` 为合法且不依赖源名形状的默认 Python 包名。`pyproject.toml` 定义可安装的图包及所需依赖，包名与 CLI 指向实际生成文件的路径一致；Python 按 `skill_graph` 导入，不把 `src` 当通用导入前缀。运行资源相对搬移后的应用或模块位置定位，业务工作文件仍按任务上下文处理。

源名保留在原包中，graph ID 在目标规则允许时沿用源名，必要映射在 README 中记录。配置示例按需增加，实际凭据由环境提供。没有配置需要时不创建空 `.env` 或多余模板。

README 说明调用映射、依赖和权限前提、模型配置、Python 与 `langgraph` CLI 调用、适用的暂停恢复方法及尚未取得的运行证据。资源搬移并不消除外部依赖。

未选方案是把源资源、转换器工具和新图代码混放在同一根目录；该方案容易冲突，且难以区分图运行需要的内容。

### 4. 图代码按源局部语义组装

固定约束使用 `StateGraph` 节点和边，自主区段满足源约束时采用 `langchain.agents.create_agent`，混合流程组合二者。纯自主流程可直接导出 agent 图，工具调用本身不构成手写模型循环的理由。

Agent 负责确定业务数据、节点边界和模型判断依据。代码判断明确数据条件，模型处理源规定的语义条件。状态保留跨节点和恢复所需信息；参考资料按需读取，不规定所有源 Skill 必须有 `messages/artifacts` 通道。

循环、并行和失败恢复的约束见 `skill-graph-generation` 规格。实现时选择合适的边、子图及恢复方式，不将节点重试策略当作失败停止的替代，也不将运行步数上限视为源停止条件。

图装配逻辑只维护一份。CLI 按配置指向编译图或工厂，Python 调用按需要传入存储、会话等运行设施；不要求两种导出并存。服务端入口采用服务提供的存储注入，普通 Python 路径不依赖服务端身份字段。

### 5. 仓库验收与发布资产分离

脚本行为测试位于 `tests/`，源包样本位于 `tests/fixtures/skills/`，验收驱动、环境声明和记录约定放在 `tests/acceptance/`。发布包只含执行需要的文件；测试环境和临时生成图不进入发布目录。

脚本单测优先使用标准库 `unittest`、临时目录和进程调用，覆盖元数据、非约定目录、复制、路径重叠、已有目标保护、结果结构以及错误配置等可观察行为；不静态断言主文件指令文本。

首版从两个受控样本起步：固定文件流程覆盖资源、脚本、分支、确认和副作用；混合检索流程覆盖语义循环、受控故障及实际模型调用。真实样本采用当前仓库已安装的 `.agents/skills/wait-what/`，在测试资产中保留源包快照和出处，提供任务原文与包含术语表的工作目录，核对它要求的上下文重述、语言风格及术语使用。原包指令不改写成测试答案，未触发的分支明确列为未覆盖范围。

执行 Agent 按发布 Skill 转换样本，验收驱动检查生成结果；不另建一个 AI 图生成器。源 Skill 与图的对照可在相同任务及受控条件下辅助审查，源契约仍是最终判据。模型相关语义检查保留人工复核位置，不引入第二套评分模型或文本相似度门槛。

`tests/acceptance/requirements.txt` 声明本地参考基线的 LangGraph、LangChain、langchain-core、CLI 及实际选定模型所需依赖；模型选择通过显式配置提供，不捆绑默认供应商。环境准备复用项目允许的工具链；当前共享环境缺少这些运行依赖，后续实施时核对并按项目依赖管理规则准备，不在本次规划安装。

单元测试不默认触发模型或服务。真实验收显式执行并记录配置、观察和限制：一条入口深入覆盖业务，另一条覆盖基本调用及适用的暂停恢复差异；在新目录验证资源搬移。服务连接由验收环境配置，不把开发服务启动作为默认单测副作用。依赖缺失保留受阻项，不以跳过或替身通过冒充真实验收完成。

### 6. 资料校正和实施顺序

先固定辅助脚本契约及行为检查，再写完整主文件与必要参考，按样本实际执行转换、运行和搬移验证。根目录 `references/skill-to-langgraph-mapping.md`、`langgraph-core.md`、`langchain-cli-and-deployment.md` 的设计建议同步校正；API 事实与转换策略分别表达，保留原始来源。

规格按四个能力边界组织，已确认决策留在原议题中供追溯；实现规则以规格及最终主文件为准，不新建一套并行的决策文档。

## Risks / Trade-offs

- 自然语言的条件和质量要求不能由静态脚本证明 → 保留模型判断与人工复核，并报告具体覆盖范围。
- 完整复制可能增加产物体积 → 首版以资源保真为先，不用静态引用裁剪；无法完整复制时显式失败。
- 外部操作在故障恢复时可能重复 → 选择实际有效的恢复边界或工具幂等支持，无法保证时声明限制。
- 真实模型输出有变化 → 验收源规定的行为与内容，保留真实观察，不锁定未约定的措辞。
- 验收依赖或凭据可能未就绪 → 分开报告环境受阻和图逻辑问题，保留未完成项；产物生成不依赖真实服务已接入。
- 开发参考与已确认决策存在差异 → 实施任务显式包含资料校正，发布时仅保留当前规则和必要说明。

## Migration Plan

本项目无需数据或旧接口迁移。按 tasks 实现发布文件与仓库验收资产，已有源包和用户文件保持原样；实施进度以 tasks 的复选框和仓库验收记录为准。2026-10-23 按用户决定拆分交付范围：本轮以已实现内容及已有证据结项，原 5.2、5.4 验收迁入 `compile-skill-runtime-responsibilities`，保真标准与失败证据保留。
