# Proposal

## Why

仓库已有宏观目标、开发参考和七项已确认决策，但发布目录尚无可执行的 Skill 包。需要将这些决策落实为可独立使用的转换指令、确定性辅助脚本和有证据边界的验收流程，使 Agent 能从合法源 Skill 包生成保持源行为的 LangGraph 应用。

## What Changes

- 在 `skill-to-graph/` 发布符合 Agent Skills 规范的 Skill 包，核心执行契约集中于 `SKILL.md`，按需分发映射解释与必要 API 资料。
- 将合法源包路径作为唯一必需转换输入，提供包检查、资源盘点和完整复制能力，以及生成产物的确定性检查。
- 由 Agent 识别源契约并生成具体 Python 图：固定流程显式控制，自主决策保留模型判断，混合流程组合两者。
- 生成包含完整源包、图代码、`langgraph.json`、依赖声明及运行说明的可搬移应用；支持 Python 与 CLI，显式声明外部运行条件。
- 在仓库内准备少量受控样本、至少一个真实 Skill 和最小验收环境，分别记录真实能力、替身与未验证范围的证据。
- 校正根目录开发资料中与已确认决策不一致的转换建议。

## Capabilities

### New Capabilities

- `skill-package-processing`：合法源包的检查、盘点、完整复制及安全输出位置处理。
- `skill-graph-generation`：源业务契约与流程语义到图控制流、模型行为和运行能力的保真转换。
- `graph-artifact-delivery`：图应用的调用封装、资源分发、入口配置、依赖声明及确定性产物检查。
- `conversion-acceptance`：代表性样本、仓库验收环境、双入口和搬移验证及证据判定。

### Modified Capabilities

无。当前 `openspec/specs/` 尚无已有能力规格。

## Impact

- 2026-10-23 范围调整：本 change 交付首版实现、验收基础和已有证据；原任务 5.2、5.4 的完整保真及整体验收正式移入 `compile-skill-runtime-responsibilities`，本轮不再以它们作为结项条件。项目目标和规格保持不变，迁移不将失败结果改判通过。

- 新增发布包核心文件、执行参考和两类辅助脚本；复用成熟解析与文件操作能力，不引入工作流中间语言、通用编译器或数据库。
- 新增仓库内脚本行为测试、样本和验收环境声明；这些资产不进入发布 Skill 包或生成图。
- 生成图按需要声明 LangGraph、LangChain 及相关运行依赖；转换器检查与复制源包不要求目标模型、外部服务或 CLI 已可运行。
- 首版验收以现有参考中的版本基线为起点，模型、服务和凭据在运行时配置。依赖安装和服务启动依项目授权规则执行，验收环境留在发布目录外。
