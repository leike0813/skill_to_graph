# Design

## Context

动机与范围见 [proposal.md](proposal.md)。发布包当前为 212 行主文件、两份参考资料和三个 Python 模块；`_cli.py` 是内部公共结果协议，另两个模块提供正式命令。主文件已有完整六步主流程、完成条件和结果表，不需要重建工作流。

本设计依据 skill-smith 的复杂度模型、职责边界及质量清单，并采用 writing-for-agents 的单一事实源和按调用时机组织原则。开发依据包括当前发布包、四份主规格、`GLOSSARY.md`、决策地图及现有验收说明。已有官方来源支持当前 API 基线；本次不改变 API 选择和版本，无需重新开展外部研究。

### 审查发现

| 位置 | 观察 | 执行风险与优化方向 |
| --- | --- | --- |
| `SKILL.md:9-26` 及各步骤 | 目标、职责、非目标和禁止行为分散在开篇与步骤中，内容多数已经存在 | 重组为可定位的运行契约；保留步骤中的特定条件，避免复制同一规则 |
| `SKILL.md:80-100` | 职责局部化、上下文传递、恢复、权限和失败策略集中为连续段落 | 按执行者所需输入、控制与恢复等决策组织，避免弱化纯自主流程例外和正式修正路径 |
| `references/runtime-api.md:39,69-80` | 嵌套 agent 的 config 传递、服务工厂签名限制及恢复标识主要由参考资料解释 | 主文件提炼执行所需条件和核对动作；具体代码与 HTTP 示例留在参考资料 |
| `scripts/skill_package.py:116-126`、`scripts/check_graph.py:main` | 帮助已有功能和参数，但缺少完整的结果说明、调用示例及子命令写入边界 | 只调整 argparse 帮助元数据，使独立 `--help` 调用足以确定用途和副作用 |
| `SKILL.md:158-182` | 已严格区分静态检查、真实调用及保真证据 | 保持该边界；文字精简不能将多个结论合为“验收成功” |

以上是指令组织和可发现性问题，不据此断言现有转换功能失败。参考资料中的 API 说明仍有实际价值，两个文件均保留。

## Goals / Non-Goals

**Goals:**

- 让执行 Agent 从主文件取得完整任务、决策顺序、职责和失败处理，再按时机使用参考示例。
- 同一规则有明确的权威位置；跨步骤需要使用时指向该规则，案例只解释应用，不另立协议。
- 命令帮助可独立理解；已有业务参数、结果 schema、退出码、写入及校验行为保持不变。

**Non-Goals:**

- 不扩展源 Skill 支持范围、图能力、模型供应商、部署形态或转换产物契约。
- 不引入 gate、SQLite、模板渲染器、新命令、固定工作表文件格式或 Skill 执行子代理机制。
- 不改历史生成图和验收记录，不将文档审查或旧图运行结果当作新版转换证据。

## Decisions

### 1. 保持 Tier 3：脚本辅助工作流

包解析、完整复制和静态检查需要确定性脚本，纯文本的 Tier 1/2 不足以覆盖现有职责。现有阶段完成条件已表达推进依据，用户未要求转换器跨会话恢复或新增机器调用协议，不引入更重的状态机。生成图的运行恢复需求与转换 Skill 自身的持久化需求分别判断。

未来只有明确出现转换任务跨会话恢复、权威中间状态或受控 runner 协议需求，才重新评估架构厚度；这不是本次交付的一部分。

### 2. 主文件组织为最小完备执行契约

使用目标与非目标、输入输出及保真边界、LLM/脚本职责、禁止事项、执行流程、命令结果与失败处理等可定位章节。所有内容从现有规则提炼，不为凑章节增加无实际风险的禁止事项。

保持检查源包、提取契约、选择结构、创建应用、验证、交付六步。每步继续包含输入、决策、完成条件和相应失败处理；脚本命令仍在实际调用步骤中，参考资料仍在需要它们的位置直接链接。frontmatter 只精炼能力与触发场景，保留现有运行依赖声明。

对第 3 步按职责与输入、状态与上下文、控制与恢复、能力接入组织。必须同时保留：多阶段局部指令、纯自主例外、约束实际可见性、委派证据边界、源停止条件、暂停重跑副作用、源失败策略及源允许的修正路径。不能用一个“保持保真”口号替代这些执行规则。

不采用只减少行数的全篇压缩，也不把所有约束集中到长清单后从步骤中消除必要的适用条件。

### 3. 参考资料保留示例，必要规则回到主文件

对两份参考资料逐段区分规则与解释。将当前主文件未表达的必要内容提炼为简短约束，例如：调用嵌套 agent 时传递适用运行配置；CLI 工厂满足目标服务的完整签名约定；恢复沿用对应会话和检查点；内存示例的恢复范围限于存活进程。适用条件必须一起保留，不能因此强制所有图导出工厂、提供持久化或增加供应商配置字段。

参考资料继续提供 `StateGraph`、`create_agent`、暂停、服务入口、职责映射及保真反例。与主文件重复的规范性段落改为具体解释或示例，官方来源及版本基线保留。不新增碎片参考文件，也不把主流程移入 references。

### 4. 帮助改动止于 argparse 元数据

在两个命令及 `inspect`、`copy` 子命令的帮助中使用清楚的 description/epilog 和示例，说明真实输入、成功与失败的 JSON 外壳、退出码含义、只读或创建新目录的行为及静态检查边界。结果字段与枚举直接取现有协议，不另建 schema 文件或公共帮助框架。

不改解析器控制流、`_cli.py`、业务函数和调用方。现有测试只核对帮助可用、成功退出及无 JSON 副作用，不添加整段帮助文字断言。

### 5. 用契约语义复核区分验证层次

执行前后逐项对照四份主规格及原指令义务，确认每项在新主文件中有明确位置，两个 references 均有用途与读取时机。检查脚本调用、枚举和失败路径，按 skill-smith 的质量清单人工判断；不写指令文本测试或关键词评分器。

轻量场景复用已有材料：固定文件转换、含语义判断及确认的混合流程、纯自主流程、目标目录冲突、外部运行依赖缺失，以及跨阶段约束和提交后修正。复核其应走的分支和不能声称的证据；这些是语义审阅，不计作真实运行。

本次实现的最小验证为：既有 14 项脚本测试；正式命令和子命令 `--help`；对发布包执行只读 `inspect`；`git diff --check`。不安装依赖，不启动服务。

正式 with-skill/baseline 对照及真实模型重新转换不设为本次指令重构的默认任务。旧验收资产继续作为场景与历史事实；若要声称新版转换效果经运行验证，应另在新目录生成图并按现有验收契约取证，所需模型、服务及写入授权必须已具备。

| 文件 | 预期变化 |

| `skill-to-graph/SKILL.md` | 重组运行契约与职责，提炼必要规则，保留流程、命令、结果协议和完成条件 |
| `skill-to-graph/references/runtime-api.md` | 保留 API 代码及解释，必要约束在主文件有权威表述 |

无新增或删除发布文件。测试、fixture、验收驱动、导出与配置不需修改：脚本路径、签名、参数和结果完全保持。`_cli.py`、根目录开发参考资料与 `AGENTS.md` 无需更新。若实施发现必须改变行为，先修订本 change 的范围及 specs 决策，不能借重写指令隐式扩大任务。

## Risks / Trade-offs

- [精简丢失适用条件] → 逐义务核对源位置与新位置，重点复核权限、纯自主例外、恢复及修正路径。
- [主文件与参考资料各维护一份规范] → 主文件作为规则权威，参考资料用示例解释；API 细节按明确时机读取。
- [脚本测试通过被误解为提示词效果提升] → 单独报告脚本验证和人工语义审阅，未重新转换就不声明新版运行保真或质量提升。
- [帮助文字泄露本机路径或模型配置] → 使用通用路径和合成调用示例；发布文件不引用仓库专用环境或凭据。
