# 用《Attention Is All You Need》测试 Skill 转图

2026-10-22

本轮已下载论文、完成 MinerU 转换，并用同一份 Markdown 跑完原 Skill 和转换图。两组都生成了完整分析文件，但**转换图尚未通过保真验收**：要求中文输出，引文报告却大段使用英文。原 Skill 的对照执行也出现事实错误、最终 JSON 被改写和子代理越界读取，不能把对照组当作正确答案。

论文是 [arXiv:1706.03762](https://arxiv.org/abs/1706.03762)。[原 PDF](input/attention-is-all-you-need.pdf) 共 15 页，已用 MinerU VLM 转为 [Markdown](input/mineru/attention-is-all-you-need.md)，保留公式、表格及配图。两组均输入这份 Markdown，语言为 `zh-CN`，执行完整分析；数据库记录的输入哈希一致。主代理与批次子代理都使用指定的 `minimax-code-cn/MiniMax-M3.1-Flash`，没有换模型补做结果。

对照组由 omp 直接读取并执行源 Skill。实验组将源包完整复制到图应用中，由 LangGraph 调度计划、摘要、评分、参考文献和引文分析，语义判断仍交给真实模型；原 Skill 的脚本负责数据库、校验和最终渲染。源包副本与当前原包的 72 个文件逐一比对一致。没有修改原包或手工修订两组最终产物。

可以直接阅读两组产物：[对照组摘要](control/artifacts/digest.md)、[图的摘要](graph-run/artifacts/digest.md)，以及[对照组引文报告](control/artifacts/citation_analysis.md)、[图的引文报告](graph-run/artifacts/citation_analysis.md)。另外四份文件是各自目录中的 `references.json`、`citation_analysis.json`、`literature_matching_metadata.json` 和 `literature_score.json`。

**图的问题已经影响交付内容。** 源 Skill 明确规定 `language` 控制摘要和引文报告。图的引文 JSON 虽标着 `zh-CN`，总体总结却以 “Within the Introduction and Background scope…” 开头，多数逐条总结也使用英文。检查语言标签无法发现这个错误。

从实现看，初始化把语言写入了数据库，但阶段代理和批次代理没有得到语言的明确取值；提示只说“遵循数据库里的语言”。另一个问题是，图在首次提交推进阶段后阻止再次提交。记录中已经出现模型写出的 `citation_payload_zh.json`，却没有第二次成功提交，最终报告仍是英文。这说明当前的阶段限制还妨碍了修正。代码和草稿均保留，后续应修正语言传递及必要的修订路径，再在新目录验收。本轮没有把旧产物覆盖成中文来制造通过结果。

**事实抽查也说明“跑完”不等于“分析正确”。** 对照组摘要把 Transformer 半监督句法分析结果写成 91.3 F1，并据此说低于 92.1。论文表 4 给出的值是 92.7；91.3 对应 WSJ-only 设置。对照组还声称表 2、3、4 等内容被省略号截断，目前输入中没有找到支持这一说法的依据。

图的摘要正确区分了 91.3 与 92.7，也指出英法 BLEU 数值存在差异。不过它把 dropout 写成“base 为 0.3”，与正文明确给出的 base 为 0.1 不符。因此两组摘要都需要人工核对。

41.8 与 41.0 要单独说明：检查下载的 PDF 后，摘要和表 2 的确写着 41.8，6.1 节正文则写着 41.0。MinerU Markdown 保留了这个差异。本轮没有修改输入去统一数字；报告中指出差异比直接选一个数更忠实。

**对照组的执行方式也暴露了约束问题。** omp 的最后一条回复把 JSON 放进代码围栏，并把完整输入哈希从 64 位截短为 42 位。数据库和 runtime 生成的结果镜像仍保留完整哈希，错误出在代理转述最终结果时。原始回复已另存为 [observed-final-response.txt](control/observed-final-response.txt)，没有替它修正。

此外，对照组的 metadata 子代理读取了源实现、测试 README 等分配批次之外的文件，citation 子代理也读取了其他批次草稿或 manifest。源 Skill 要求子代理只消费分配的 batch。现有会话记录因此不能支持“对照执行完全遵守源要求”的结论。检查到的子代理调用中未见联网工具或网络命令，但批次隔离已经失败。这轮仍可用于发现问题，不能当作严格隔离的质量对比实验。

运行中发生的问题也予以保留。图最初两次启动分别因计划阶段缺 payload、相对参考文档路径解析错误而中止；修正适配代码后，从已有 DB 恢复完成第三次运行。第三次中，源 runtime 拒绝过不合法的摘要结构和没有本地证据支持的 metadata 字段，模型修改 payload 后通过。对照组首次委派则因 omp 不接受 `model` 参数而失败，随后移除该参数，实际子代理会话仍使用配置中的指定模型。这些修复不代表所有失败恢复分支都已覆盖。

对照组从会话开始到最后回复约 13 分 56 秒；图第三次运行约 9 分 31 秒，但此前已有两次失败和人工修复，运行方式也不同。这些时长只记录经过，不据此比较性能或成本。

自动检查的原始结果在 [comparison.json](comparison.json)，执行与批次证据在 [execution-evidence.json](execution-evidence.json)，图静态检查在 [static-check.json](static-check.json)。`compare.py` 退出 1 是预期结果：它检出了对照组最终回复不是裸 JSON、与镜像不一致这两项问题。图通过的是这里实现的结构检查，语言和事实错误来自另外的人工复核。

本轮未测试该图的 CLI 服务入口、`score_only`、低质量参考文献分支及完整搬移运行，也未逐条核验所有参考元数据、引文解释与评分理由。单篇论文、每组一次完成的结果不足以衡量质量稳定性。上一轮自然语言样例的保真缺口仍在；完整保真和整体验收任务已于 2026-10-23 按用户决定迁入 `compile-skill-runtime-responsibilities` 的 3.1、3.2，继续保持未完成，首轮按调整后的实现交付范围结项。
