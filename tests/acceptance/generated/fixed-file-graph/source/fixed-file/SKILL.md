# 固定流程写文件

把 CSV 中的 count 列求和，用包内模板渲染出一份摘要，经用户确认后写入指定输出目录。
流程按固定次序推进：校验、计算、确认、写入。校验和读写出错时停止并返回错误；
流程中唯一的分支是确认处的写入决定：用户批准才写，没有批准就不产生任何文件。

## 输入

- `source_csv`：CSV 文件路径，UTF-8 编码。
- `output_dir`：摘要文件的输出目录路径。
- `approved`：用户对写入确认问题的回复。只接受明确的 `true` 视为批准，其余回复一律视为未批准。

`source_csv` 和 `output_dir` 由调用方在首次调用时提供；缺失或含义不清时先问清楚，不要猜。
`approved` 不要求提前提供，它在第 3 步提出确认问题后由用户回复得到。

## 步骤

### 1. 校验 CSV

读取 `source_csv`，要求：

- 文件存在且为 UTF-8 编码；
- 表头含必需列 `name` 和 `count`；
- 每行数据行的 `count` 是非负整数（只允许十进制数字，不接受负号、小数点或空值）；
- 空白行忽略。

任一条不满足就停止，不写任何文件，也不做重试。向调用方返回结构化错误，说明失败条件和位置。

### 2. 计算并生成计划

用包内脚本读取 CSV 和模板，得到行数 `rows`、总和 `total` 和渲染后的文件内容：

```sh
python scripts/render.py <source_csv>
```

模板默认是包内 `templates/summary.txt`，内容格式为 `Total: {total}` 加一个换行；模板只支持 `{total}` 一个占位符。
脚本只读文件并向标准输出打印 JSON 计划，不创建、不修改任何文件。
脚本失败时按其退出码和错误码停止，不重试、不改用其他方式读 CSV。

行数与总和的对应关系：

- `rows` 是数据行数（不含表头，忽略空白行）；
- `total` 是所有数据行 `count` 的总和。

### 3. 请求确认

把计划内容（`rows`、`total`、将要写入的路径）说清楚，向用户提出一个明确的二选一确认问题：请用户回复 `true` 批准写入，或回复 `false` 放弃。

在收到用户回复之前，不要创建输出目录，不要写任何业务文件。

### 4. 按回复处理

- 回复不是 `true`（包括 `false`、空回复、其他内容）：返回 `cancelled`，不写任何文件。
- 回复是 `true`：
  - 目标文件是 `<output_dir>/summary.txt`；
  - `output_dir` 不存在就创建它；
  - 目标文件已存在就失败，不覆盖已有内容，返回结构化错误并说明该路径；
  - 写入的内容是脚本给出的渲染结果，不自己另写一份。

文件写入出错时停止，不重试、不换路径重试。已写出的部分内容按实际发生报告，不当作成功。

## 输出

成功写入时返回：

- `status`：`ok`
- `rows`：数据行数
- `total`：count 总和
- `path`：实际写入的文件路径

未批准时返回：

- `status`：`cancelled`
- `rows`、`total`：来自计划
- `path`：不出现

失败时返回结构化错误：`status` 为 `error`，并带错误码、失败位置和原因。不要用状态字符串代替实际文件，文件是否真的存在由写入方确认。

## 脚本说明

`scripts/render.py` 只做确定性计算：读 CSV、读模板、打印 JSON 计划。写入由执行者用真实的文件写入能力完成，不要让脚本承担写入，也不要用脚本的成功返回推断文件已存在。

脚本成功时退出码 0，打印 JSON 计划；失败时退出码非 0，打印含错误码的 JSON。
