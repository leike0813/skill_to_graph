# 从源语义选择结构

本文在提取源契约和选择结构时读取，给出主文件规则的应用例子。

| 源行为 | 可选实现 | 需要核对的观察 |
| --- | --- | --- |
| 校验输入，再生成文件 | 固定校验节点→文件节点 | 无效输入不能写文件 |
| 自主分析和使用工具 | 直接导出 create_agent 的图 | 任务上下文、工具选择及失败语义保持 |
| 检查输入、自主检索、确认、写报告 | StateGraph 中连接 agent 子图、确认节点、写节点 | 检索自主性和确认前无写入同时成立 |
| 证据不足时继续检索 | 模型判断并选择检索或结束 | 不能用检索次数冒充充分性 |
| 按输入顺序逐项处理 | 默认顺序循环 | 输出、错误及副作用与原项目对应 |
| 源明确许可独立任务并行 | Send 或并行边加适当 reducer | 完成顺序不能打乱约定的汇总顺序 |

编号可能只是描述顺序，并不表示每条都要一个节点。将校验、暂停和不可逆操作分开，通常比按段落拆分更能解释恢复行为。

## 职责与运行上下文

以一份含计划、摘要、评分和引文分析的 Skill 为例，转换 Agent 先阅读完整源包，再形成这样的分配：

| 源义务 | 执行者和输入 | 实现及可观察结果 |
| --- | --- | --- |
| 先计划后摘要 | 图路由；当前阶段 | 摘要执行前已有正式计划 |
| 按指定语言写报告 | 摘要/引文节点及引文批次代理；实际 language 值 | 正文遵守语言要求，原文标题和引句按源规则保留 |
| 子代理只读分配批次 | 批次代理；本批次证据及适用规则 | 只能取得自身批次，合并与正式提交由主执行者完成 |
| 按证据作评分 | 评分节点；规范化原文、rubric、允许编辑字段 | 模型形成判断，脚本保留锁定项并校验提交 |
| 可经正式提交修正 | 源指定的执行者；当前结果及修正依据 | 发现不合规内容后仍能走源允许的提交和重渲染路径 |

摘要节点的局部指令可描述“根据这些原文证据和大纲，按指定语言生成这些结构化槽位”，无需再解释后续参考文献和评分的全流程。跨多个职责适用的规则在相应接收点提供；完整源包仍按原布局携带。

如果一份 Skill 只规定自主调查目标，没有可独立固定的阶段，完整任务可以保留为一个 agent 区段。局部化以保持职责为准，不以提示词长度为准。

## 文件和资源

若源要求 `report.csv`，框架返回一个说明字符串不算生成文件。输入路径、目标目录、编码、列和覆写政策均来自源。业务文件位置从任务上下文取得；模板路径从携带的 `source/<源包名>/` 取得。

源脚本可能按参数选取 `templates/` 中不同文件。即便当前场景只用一份，完整快照也保留其余文件。参考资料的存在不意味着需要在开始时读取；可以提供受作用域限制的读取工具，在源规定的条件下调用。

## 暂停和恢复

确认节点只形成问题并调用 `interrupt()`，后续节点才执行写入。恢复时使用相同 thread 标识和 `Command(resume=回复)`，接入真正持久的检查点或明确进程内限制。外部操作完成但结果尚未记录时仍可能重跑；若服务支持幂等键，可按源许可采用，否则说明恢复限制。

## 自主性和权限

源要求“直到足够支持结论”时，让模型根据证据决定停止。输入、上下文和工具结果应能支持这个判断。技术运行上限是资源边界；触发后留下受限状态，不能自动给出业务成功。

平台的工具预授权清单只决定免确认的范围时，未列出的工具仍可能在取得授权后使用。禁止调用、可调用但需授权、已预授权是不同状态。图的工具实现和环境的授权机制一起实现这些语义。

## 保真复核例子

观察最终内容还不够。两个图可能输出相同报告，但一个在确认前已写文件；后者违背源。另一对图拓扑相同，却将充分性判断改成固定三次检索，也违背源。工作表应把每条约束链接到行为证据，并记录没触发的分支。

引文 JSON 的 language 标成中文，而 summary 和报告正文仍为英文，是语言违约。检查主键覆盖和渲染一致性都无法判断这一点。可分别核对代理实际收到的语言值、批次权限、最终正文及正式修正后的产物；保留初次提交，才能分清修正和首次成功。
